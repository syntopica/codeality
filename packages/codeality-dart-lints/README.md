# codeality_lints

The lint set [`codeality-dart`](../codeality-dart) enforces, for Dart and
Flutter projects.

## Use

Add it as a dev dependency:

```yaml
dev_dependencies:
  codeality_lints: ^0.1.0
```

Then include one of the two sets from `analysis_options.yaml`:

```yaml
# Pure Dart package
include: package:codeality_lints/analysis_options.yaml
```

```yaml
# Flutter app or package
include: package:codeality_lints/flutter.yaml
```

`codeality-dart init` does both for you.

## What is in it

- every rule of `package:lints` 6.1.0 `core` and `recommended`;
- in `flutter.yaml`, the rules `package:flutter_lints` 6.0.0 adds;
- `strict-casts`, `strict-inference` and `strict-raw-types`;
- a strict set: `prefer_final_locals`, `prefer_const_constructors`,
  `always_declare_return_types`, `avoid_print`, `unawaited_futures`,
  `avoid_dynamic_calls`, `close_sinks`, `directives_ordering` and others - see
  the files.

The upstream lists are inlined rather than included, so this package has no
dependencies and never constrains your version solve. Lints report as infos;
`codeality-dart gate` runs `dart analyze --fatal-infos`, which fails on them.

## Maintaining

`lib/*.yaml` are generated by `tool/generate.py` from the pub cache copies of
the pinned upstream versions. `tool/verify_lints.sh` proves both sets load and
fire, and that none names a rule the installed SDK does not know.
